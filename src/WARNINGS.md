# Suppressed Warnings

This document explains each warning suppressed via `<NoWarn>` in
`N2.Core.Abstractions/N2.Core.Abstractions.csproj`.

Because this library contains **only interfaces, abstract base types, and simple model classes**,
several analyser rules that apply to concrete implementations are intentionally silenced.

| Warning | Analyser | Name | Reason for suppression | Severity | Safe to ignore when |
|---------|----------|------|------------------------|----------|---------------------|
| `CA1002` | Roslyn / CA | Do not expose generic lists | Public API surfaces on response types intentionally expose `List<T>` for ease of use by consumers. | Designer choice | The type is a data-transfer or response model owned by this library and mutability by the caller is acceptable. Re-evaluate if the type crosses a trust boundary. |
| `CA1040` | Roslyn / CA | Avoid empty interfaces | Marker interfaces (e.g. `ICommandRequest`) are a deliberate part of the command-pattern design. | Designer choice | The interface is used as a generic constraint or for type discrimination, not as a behavioural contract. Safe as long as the marker pattern is the documented intent. |
| `CA1055` | Roslyn / CA | URI return values should not be strings | URL/URI properties are typed as `string` to keep the abstraction free of `System.Uri` coupling. | Low | The value is an opaque string that consumers parse themselves, or it originates from config/user input that has not been validated as a well-formed URI. |
| `CA1308` | Roslyn / CA | Normalize strings to uppercase | Some identifiers are intentionally lowercased (e.g. slug generation, claim values). | Low | The lowercased string is used for display, routing, or external system compatibility — not for ordinal security comparisons where case folding matters. |
| `CA1510` | Roslyn / CA | Use Use ArgumentNullException throw helpers | The library targets .NET Standard 2.0 where throw helpers are not available. | Low | The codebase targets a framework version that does not support throw helpers. Consider migrating to .NET 6+ in the future to take advantage of this performance improvement. |
| `CA1707` | Roslyn / CA | Identifiers should not contain underscores | Test methods use underscore-separated names (`Given_When_Then`). | Designer choice | The identifier is a test method name following a team-agreed naming convention. Never suppress in production library code. |
| `CA1812` | Roslyn / CA | Avoid uninstantiated internal classes | Internal types in an abstractions library are instantiated by consumer projects, not by this one. | Low | The class is registered via dependency injection or reflection in a consumer assembly. Safe as long as there is a known external instantiation path. |
| `CA1819` | Roslyn / CA | Properties should not return arrays | Some model types expose `byte[]` or `string[]` properties by design (e.g. document content). | Low | The property is on a simple DTO/model with no defensive-copy requirement, and callers are trusted not to mutate shared state. Re-evaluate for types in public security-sensitive APIs. |
| `CA1859` | Roslyn / CA | Use concrete types when possible for improved performance | Return types are intentionally kept as interfaces/abstractions to honour the library's contract. | Low | The return type is an interface by design (abstraction library). The marginal virtual-dispatch cost is acceptable; consumers may substitute any implementation. |
| `CA2007` | Roslyn / CA | Do not directly await a Task without ConfigureAwait | Consumers decide synchronisation-context behaviour; mandating it in abstractions is inappropriate. | Medium | The code runs in a context where there is no `SynchronizationContext` (ASP.NET Core, console, worker service). **Do not suppress** in UI-framework code (WPF, WinForms, MAUI) where deadlocks are possible. |
| `CS1591` | C# compiler | Missing XML comment for publicly visible type or member | Documentation is being added incrementally. | Low | The member is internal implementation detail that does not appear in the published NuGet docs. Public API members should be documented before release. |
| `IDE0060` | Roslyn / IDE | Remove unused parameter | Interface and abstract method signatures must match the defined contract regardless of whether an individual implementation uses the parameter. | Designer choice | The parameter exists because the interface contract requires it. Safe to suppress on explicit interface implementations and overrides; do not suppress on standalone methods. |
| `IDE0290` | Roslyn / IDE | Use primary constructor | Block-body constructors are kept for cross-framework consistency and readability. | Designer choice | The type has no invariant logic in the constructor and targets frameworks where primary constructors are fully supported. Suppressed globally for style consistency. |
| `RCS1021` | Roslynator | Use expression body for lambda | Multi-statement lambdas are kept in block form for readability. | Designer choice | Always safe to ignore; this is a pure style rule with no correctness or performance implications. |
| `RMG020` | Mapperly | Source member is not mapped to any target member | Partial mappings are intentional; not every source field has a corresponding target. | Medium | The unmapped source member is deliberately excluded (e.g. internal audit field, computed property). Verify the exclusion is explicit and documented to avoid silent data loss when the source type gains new members. |
| `S125` | SonarAnalyzer | Sections of code should not be commented-out | Commented-out code is used during active development. | Low | The comment documents an intentionally removed alternative or is a reference snippet. Should be cleaned up before merging to the main branch; not appropriate to leave permanently. |
| `S1135` | SonarAnalyzer | Track uses of "TODO" tags | TODO comments are tracked manually in the backlog rather than as build errors. | Low | The TODO is linked to a known backlog item and does not represent a correctness gap in the current release. All TODOs should be resolved before a major version bump. |
| `S2094` | SonarAnalyzer | Classes should not be empty | Empty classes serve as typed exception base classes or marker types in the public API. | Designer choice | The class provides a distinct type identity (e.g. a named exception or base class for extensibility). Safe as long as the empty body is the deliberate final design, not an incomplete implementation. |
